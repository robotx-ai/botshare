Overview

BotShare (botsharing.us) is a robot service rental booking platform. Next.js 13 (App Router + a single Pages-Router route for NextAuth), Tailwind, Prisma on Supabase Postgres, Stripe Checkout, Cloudinary media, Resend email, MapLibre maps. Deployed to Netlify.

AGENTS.md / CLAUDE.md are the source of truth for product copy, terminology, and guardrails. This page is a quick operational reference, not a replacement.

Local setup

git clone <repo> && cd botshare
npm install
cp .env.example .env        # fill in values (see Environment vars)
npx prisma generate         # generate the Prisma client
npm run dev                 # http://localhost:3000
Node version: use Node 20 (Netlify builds on 20). The production next build can stall on newer majors in some shells — match the deploy runtime.

Testing & checks

There is no npm test script. The pre-merge gate is lint + types + build, plus manual UI verification.

npm run lint                      # ESLint (zero warnings expected)
npx tsc --noEmit -p tsconfig.json # type-check the whole project
npm run build                     # full production build (Node 20)

Manual UI verification

For visual/flow changes, run the dev server and drive it in a browser (Playwright works well). Check key breakpoints (320 / 768 / 1024 / 1440) and the console for hydration errors.

Known benign warning: a next/font hydration notice on the homepage hero (Barlow) in dev — clears in a clean production build.

Deployment

Netlify project hifivebot-com (79afde94-…), serving hifivebot.com. The repo is git-linked: a push to main builds on Netlify CI. Nothing goes live from that build on its own.

Auto-publishing is deliberately off — the published deploy is kept locked, so each CI build finishes as a ready-but-unpublished deploy with its own URL. Every push is effectively a preview; going live is a separate, explicit act.

git push origin main       # -> CI build; preview only, never goes live
npm run deploy:promote     # publish a built deploy to hifivebot.com
npm run deploy:rollback    # instant revert
StepNotes
DefaultPush, let CI build, check the deploy URL, then deploy:promote (or the /prod-deploy skill).
Build sourceCI builds the pushed commit, not your working tree. deploy:local is the only thing that builds locally.
Promotion costPublishing is an API call — instant, no rebuild, no build minutes, nothing uploaded.
Preflightpromote-deploy.mjs refuses to publish unless the target renders real DB rows — catches a function missing the Prisma rhel engine.
Env varsManaged in the Netlify dashboard (DATABASE_URL, SUPABASE_*, NEXTAUTH_*, STRIPE_*, RESEND_*, CLOUDINARY_*). .env is local only.
If build failsNothing is published — the live site keeps serving the locked deploy.

Database & Prisma

Supabase Postgres via Prisma. Schema in prisma/schema.prisma. Models: User, Account, Listing, Reservation, UserFavorite, EmailVerificationCode. Enums: UserType, Metro.

Schema-change workflow

1. edit prisma/schema.prisma
2. create the migration SQL under prisma/migrations/<ts>_<name>/migration.sql
3. npx prisma generate          # update the client/types (local)
4. apply to Supabase (see below)
5. npm run lint && npx tsc --noEmit
Migrations here are hand-authored SQL applied out-of-band (Supabase), not via prisma migrate deploy. Singleton client: lib/prismadb.ts. Reads dominate; never instantiate PrismaClient ad-hoc.

Auth & signup flow

NextAuth CredentialsProvider (email + password), Prisma adapter, JWT sessions. The "Aire" signup is a 4-step modal.

Flow

Role select → Create account → Verify email → Success, then a restyled Login.

RouteBodyBehavior
POST /api/registeremail, name, password, userType, phone?, businessName?, termsVersion?Creates user (emailVerified: null), enforces password policy, issues + emails a hashed 6-digit code. 409 on duplicate email.
POST /api/verify-emailemail, codeValidates code (10-min TTL, 6-attempt cap); sets emailVerified; deletes code.
POST /api/verify-email/resendemailRe-issues a code for an unverified account; always returns ok (no account-existence leak).
Unverified-login guard is OFF. Existing accounts have emailVerified = null; enabling the guard in [...nextauth].ts would lock them out. Backfill before enabling.

Verification emails need RESEND_API_KEY + RESEND_FROM_EMAIL on Netlify. Without them, signup still creates the account and login works — the user just gets no code.

Password policy

Enforced client (live checklist + disabled submit) and server (/api/register 400). Source of truth: lib/passwordPolicy.ts → validatePassword().

Rule: at least 8 characters, with a letter, a number, and one uppercase letter. Login is not affected (only new account creation).

Access control

  • Service catalog writes gated to providers and admins. Customers must not create/edit/delete services. Enforce at the API layer, not just UI.
  • Provider check: session.user.userType === 'PROVIDER'.
  • Admin check: isAdminEmail() in lib/adminAuth.ts (reads ADMIN_EMAILS).
  • Admin-only: /admin/orders (all bookings, filter, cross-tenant cancel) — gated by middleware.ts.
  • Cancellation: owners cancel their own; admins cancel any (DELETE /api/reservations/[id]).

Schema guardrails

  • Don't redesign the Prisma schema without explicit request.
  • Keep route shapes: /listings/[listingId], /api/listings, /api/reservations, /api/checkout.
  • Listing.category ∈ the 3 categories · Listing.price = per-day · Listing.locationValue = coverage region.
  • Reservation.stripeSessionId unique, set after checkout.
  • guestCount/roomCount/bathroomCount are legacy compat fields — don't repurpose.
  • User.userType is the canonical role flag — no parallel role booleans.

User admin tool

Local-only UI to list and delete users (cleanup of test accounts). Lives in docs/user-admin/.

node docs/user-admin/server.js
# open http://127.0.0.1:4500
AspectDetail
CredsRead from .env at runtime — never in any served/committed file.
ReachBinds 127.0.0.1 only. Not a deployed endpoint. Refuses NODE_ENV=production.
DeleteCascades to the user's listings / reservations / favorites. Counts shown first; type DELETE to confirm. No undo.
PortOverride with USER_ADMIN_PORT.
This runs against the live database. It is a developer tool — keep it local; do not expose it.
